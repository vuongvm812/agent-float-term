# Harness Floating Terminal

**A persistent F7 shell beside your AI CLI, without wrapping the CLI.**

`agent-float-term` integrates with a parent tmux server. Run `claude`, `codex`, or
`opencode` normally in a tmux pane. When an eligible AI invocation is in the
foreground, F7 opens that pane's floating shell. F7 inside the float hides it;
the shell and its jobs keep running while detached.

**Status: implemented and locally validated, ready for local source use.**
Core PTY and startup tests passed against macOS ARM64 release and packaged
binaries with tmux 3.7c, and on Debian 12 ARM64 with tmux 3.3a and 3.7c.
Claude Code 2.1.263, OpenCode 1.18.29, and Codex 0.153.4 passed isolated no-model
smoke tests. See [compatibility](docs/compatibility.md) for exact scope and counts.
The autostart/helper fix has local regression coverage; live F7 was confirmed
before the latest optimization. The latest changes reduce F7 overhead and use
terminal-default colors without rewriting global tmux styles. Deployment and
live acceptance of these latest changes are pending. Isolated benchmarks do not
measure the user's roughly one-second F7 delay or resolve the separate reported
2-5 second AI TUI startup delay. See [validation](docs/compatibility.md#latest-f7-latency-and-theme-work)
for current test evidence and pending final reruns.
**0.1.0 publication checks remain:** no release is published or GitHub CI run
recorded; Intel/Linux x86_64 archives, WSL2, and authenticated/generating sessions
remain unverified.

## Requirements

- macOS or Linux, with **tmux 3.3a or newer** installed separately.
- A terminal that delivers F7 to tmux. Some keyboards require Fn+F7.
- Your AI CLI installed normally. This project does not install AI tools.
- Rust **1.84.1**, edition **2021**, for source builds only.

Planned native release targets are macOS Apple Silicon, macOS Intel, and Linux
x86_64 (GNU libc). Linux ARM64 remains source-build-only despite local Debian 12
validation; other targets are unverified. There is no untested cross-compiled
release stage. Native Windows is unsupported. Linux archives are built on
Ubuntu 22.04 (glibc 2.35 baseline); older glibc systems and Alpine/musl are not
supported by those archives. macOS binaries are not notarized.

Release links and downloads become available only after the maintainer publishes

Until then, build from source.

Each release contains these archives plus `SHA256SUMS`:

| Platform | Archive for v0.1.0 |
| --- | --- |
| macOS Apple Silicon | `agent-float-term-v0.1.0-aarch64-apple-darwin.tar.gz` |
| macOS Intel | `agent-float-term-v0.1.0-x86_64-apple-darwin.tar.gz` |
| Linux x86_64 | `agent-float-term-v0.1.0-x86_64-unknown-linux-gnu.tar.gz` |

Example, **after v0.1.0 is published**, for macOS Apple Silicon. Change `target`
to the matching triple above. Run in a fresh download directory:

```sh
version=v0.1.0
target=aarch64-apple-darwin
archive="agent-float-term-${version}-${target}.tar.gz"
base="https://github.com/vuongvm812/agent-float-term/releases/download/${version}"
curl --fail --location --remote-name "${base}/${archive}"
curl --fail --location --remote-name "${base}/SHA256SUMS"
```

Verify the archive's hash against its exact filename in `SHA256SUMS` before
extracting. On macOS, run `shasum -a 256 "$archive"`; on Linux, run
`sha256sum "$archive"`. A mismatch means stop. Checksums detect corruption but
are not an independent signature: both files come from the same release.

```sh
tar -xzf "$archive"
"./agent-float-term-${version}-${target}/agent-float-term" install
# Only after reviewing the preview:
"./agent-float-term-${version}-${target}/agent-float-term" install --yes
export PATH="$HOME/.local/bin:$PATH"
agent-float-term --help
```

Run the installer directly from the extracted directory. It installs a
digest-addressed payload and an owned symlink at
`$HOME/.local/bin/agent-float-term`. **Do not first copy the binary to that
destination as a regular file**: the installer refuses to overwrite an unowned
regular destination. These commands modify no tmux or shell startup files.

The archive also includes `LICENSE` and this README. Integration templates are
generated by the binary; there is no separate template download. The `export`
above affects only the current shell. Add the directory to your shell's PATH
yourself if needed; nothing is fetched and piped into a shell.

### From Source

Install tmux 3.3a+ using your system's package manager, then run `tmux -V` to
check the version. Ubuntu 22.04's default tmux 3.2a is **too old**; use a trusted
newer package or build an official release from source. The project's source
installer script is for disposable CI runners, not a host installation shortcut.
Then:

```sh
git clone https://github.com/vuongvm812/agent-float-term.git
cd agent-float-term
# For a published version: git checkout v0.1.0
cargo +1.84.1 build --locked --release
./target/release/agent-float-term install
# Only after reviewing the preview:
./target/release/agent-float-term install --yes
export PATH="$HOME/.local/bin:$PATH"
```

As with an archive, run the source-built binary's installer directly rather than
copying it to `$HOME/.local/bin/agent-float-term` yourself.

### Opt-In Integration

`install` previews changes by default; `--yes` applies the reviewed installation.
With neither `--tmux-config` nor `--shell-config`, it modifies **no startup
files**. Each flag independently authorizes integration with the specified user
file; neither implies the other. Reinstalling retains existing integrations;
omitting their flags does not request their removal. `install --yes` refreshes
owned generated templates using the recorded shell kind when no shell file is
selected, without editing unselected user configs. `update` replaces only the
binary and does not refresh those templates.

To opt into tmux startup integration:

```sh
agent-float-term install --tmux-config "$HOME/.tmux.conf"
# Only after reviewing the preview:
agent-float-term install --tmux-config "$HOME/.tmux.conf" --yes
```

Select the file your server actually loads, which may instead be
`$HOME/.config/tmux/tmux.conf`; do not create a competing config just for this tool.

Shell startup integration can be selected on its own for dedicated tmux auto
startup; it does not require `--tmux-config`. For example:

```sh
agent-float-term install --shell-config "$HOME/.zshrc" --shell-kind zsh
# Repeat with --yes only if you want the proposed edits.
```

Use `--shell-kind bash` with a bash startup file. You can also pass both config
flags in one installation if you want both integrations. Dedicated startup uses
`start` and does not load your personal tmux configuration. Auto startup skips
noninteractive/non-TTY shells, command-string invocations (including empty
`-ic`/`-lic` commands), scripts, SSH sessions, and recursion or disable guards.
At a human prompt **inside existing tmux**, it quietly initializes/binds that
server without overwriting a foreign root-key binding or nesting another outer
session. Bash initializes inline; Zsh uses a one-shot `precmd` hook after earlier
prompt cleanup restores terminal descriptors, with one bounded retry.
See [startup details](docs/operations.md#existing-or-dedicated-tmux).

Do not replace your tmux configuration wholesale. For an already running server,
use `bind` to install the runtime integration there; specify its socket when
needed. An occupied key must not be silently overwritten. `--replace-key` is
the explicit opt-in to replace an existing binding.

## Use

Inside your existing tmux server:

```sh
agent-float-term bind
agent-float-term doctor
claude
# Or run codex or opencode normally, without an agent-float-term prefix.
```

For a separate tmux environment, `agent-float-term start` opens a normal shell
in a dedicated tmux environment without loading your personal tmux configuration.
Then type your AI command as usual. It is not `agent-float-term start claude`
and does not automatically launch an AI harness.

| Where you press F7 | Behavior |
| --- | --- |
| Eligible foreground `claude`, `codex`, or `opencode` in the parent pane | Show that pane's floating shell. |
| Ordinary shell, outer `nvim`, other foreground program, or ambiguous detection | Forward the key rather than claim the pane. |
| Normal input inside an owned floating shell, even while running `nvim` | Hide the float; its shell and jobs remain alive. |
| tmux command prompt or copy mode | Retain native tmux mode keys; exit the mode first to hide with F7. |

Detection must identify an eligible foreground invocation, not just find an AI
process somewhere in the process tree. Ambiguity forwards the key. A background
AI process does not make an unrelated foreground editor eligible.
Recognition uses a known interactive CLI grammar, not every mode or flag a
harness accepts. Headless/admin modes, unknown flags, and unsupported process
layouts forward the key; see [recognition limits](docs/operations.md#recognition-limits).
Verified frontends may have same-group descendant MCP/LSP or other helpers:
helper stdin must be a pipe, socket, or `/dev/null`; terminal stdout/stderr are
allowed, but any extra terminal descriptor (FD 3 or higher) blocks eligibility.

Existing servers with global `exit-unattached` or `destroy-unattached` set to
`on` are rejected to protect detached jobs. Use the dedicated server or review
those options yourself; the tool does not silently rewrite them. Owned floating
sessions locally force `detach-on-destroy on` so a destroyed float does not move
its viewer into an unrelated session.

There is **one floating shell per parent pane and only one viewer at a time**.
On first creation its working directory is the parent pane's current directory.
Thereafter its own cwd persists; moving the parent pane does not reset it.
The shell PID and jobs survive hiding/detaching, not a tmux server exit or reboot.
This is a new shell, **not an exact clone of the parent process's environment**,
shell variables, functions, or virtual environment.

Closing the parent pane preserves the owned floating session as an orphan.
Nothing automatically destroys orphan jobs. Inspect them with `sessions` and
explicitly request cleanup when you no longer need them.

### Theme And Responsiveness

The float's content and border use the terminal emulator's default foreground
and background, not a hard-coded theme or an inherited global tmux RGB popup
background. Owned pane/window styles are reset on every open; global styles and
the parent pane are left unchanged. Explicit application colors are preserved.

Transparency remains **terminal-emulator policy**: this tool changes no OS or
emulator opacity settings and does not make the popup show through to the AI
pane beneath it. Applications that explicitly paint a background remain colored;
custom tmux `pane-colours` palette overrides can also affect the result. See
[theme behavior](docs/operations.md#terminal-theme-and-opacity).

In isolated macOS clean-shell benchmarks, warm F7 attachment p50 improved from
209.7 to 113.6 ms on tmux 3.5a and from 218.2 to 116.6 ms on 3.7c. Prompt-frame
p50 was 163.3 and 162.1 ms respectively after optimization. These are not timings
of the user's full shell profile, a fix for AI CLI startup, or a 100 ms
end-to-end guarantee. See [method and limits](docs/compatibility.md#f7-benchmark).

## Configuration

Configuration lives at
`${XDG_CONFIG_HOME:-$HOME/.config}/agent-float-term/config.toml`.

```toml
key = 'F7'
width = 80
height = 80
# Optional absolute executable path; otherwise use the default shell selection.
# shell = '/bin/zsh'

# Optional explicit harness executable overrides. Use real absolute paths.
# [[harness_paths]]
# harness = 'claude'
# path = '/absolute/custom/claude'
```

`width` and `height` are popup percentages from 10 to 100. Function keys are
limited to **F1-F12**, not F13-F24; supported named keys and modifiers include
`Tab`, `C-a`, and `M-Space`. Supported harness names are `claude`,
`codex`, and `opencode`. An explicit harness path helps identify a custom
installation; it does not wrap that command. If you change the key, reapply the
binding to the intended server and review key conflicts.
Do not change the same key concurrently with `bind` or `uninstall`: tmux has no
atomic compare-and-swap for key tables. See [key ownership](docs/operations.md#existing-or-dedicated-tmux).

## Commands

| Command | Purpose |
| --- | --- |
| `install [--tmux-config PATH] [--shell-config PATH --shell-kind bash\|zsh] [--yes]` | Preview payload/symlink installation; apply with `--yes`. Startup-file integration requires its own config flag. |
| `bind [--socket PATH] [--replace-key]` | Integrate with an existing tmux server; replacement requires opt-in. |
| `start` | Open an optional dedicated tmux environment, or initialize/bind the existing server when already inside tmux. |
| `doctor [--socket PATH]` | Read-only diagnosis of dependencies, configuration, and the selected tmux server; no mutations. |
| `sessions [--socket PATH]` | Inspect owned floating sessions, including orphans. |
| `cleanup [--socket PATH] [--session NAME] [--yes]` | Explicitly remove only owned orphan sessions; preview first. |
| `update --from PATH --sha256 HASH` | Binary-only update from a local binary whose SHA-256 must match; does not refresh integration templates. |
| `rollback` | Restore the retained previous binary, if one is available. |
| `uninstall [--yes]` | Preview or explicitly remove managed installation state. |

For a nondefault server, use the same socket consistently, for example
`agent-float-term doctor --socket /absolute/path/to/tmux.sock`.
See [Operations](docs/operations.md) for cleanup, updates, and troubleshooting.

## Privacy And Safety

No telemetry and no prompt logging are built into this tool. The floating shell
is an ordinary shell with your permissions. **tmux is not a sandbox.** AI tools,
shell history, tmux scrollback, plugins, and terminal recording may independently
retain sensitive content. Do not include prompts, tokens, or private terminal
output in bug reports. See [Security](SECURITY.md).
